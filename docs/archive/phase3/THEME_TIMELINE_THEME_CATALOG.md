# 长期日记主题时间线主题目录

> Historical / paused: the active product is now the [Private Diary Recall Assistant](../../PRIVATE_RECALL_ASSISTANT.md). Do not execute the rollout or development sequence below without a new explicit decision to resume it. Runtime code has been removed; applied Phase 3A–3C data remains dormant, and never-applied 3D/v4 SQL is archived outside the migration runner.

本文为“可审核主题时间线（Phase 3A）”提供可直接复制的主题写法。主题应帮助模型从长期日记中识别有原文证据的经历、行为和变化，而不是要求模型诊断人格、疾病，或猜测日记中没有表达的动机。

## 使用原则

- 一个运行只分析一个主题。不要把工作、健康、情绪和关系等无关主题合并到同一个输入中。
- 输入可以是完整的语义描述，不需要堆砌同义关键词。推荐使用“名称：定义”；页面会把它冻结为名称、定义、纳入、排除和不确定边界五部分。
- 所有主题都会获得通用的“同篇共现不等于主题证据”、“不得补全人物关系/动机/因果”约束；页面可为具体主题添加额外纳入、排除和边界规则。友情主题另有默认邻近关系与旅行/消费内容排除规则。
- 优先要求可观察的事件、行为、感受和决定，避免使用“证明我是什么样的人”“诊断是否患病”等不可审计表述。
- 相近但目的不同的主题应分开运行。例如“身体不适与恢复”和“运动习惯”会产生不同的证据集合。
- 每个运行都会独立处理其日期范围内的 eligible 日记。更换主题会重新调用模型，不会复用另一个主题的提取结果。
- 小范围试跑和全量运行也是两个独立运行。试跑结果不能扩展或合并进后续全量运行。

## 不推荐的主题写法

| 不推荐输入 | 原因 | 更合适的写法 |
|---|---|---|
| `我的人生` | 范围过宽，几乎所有日记都可能被判为相关 | `重要决定与人生转折：记录关键选择、原因和后续结果` |
| `工作、健康、感情、学习` | 多个主题混在一起，摘要难以审计 | 分成四个独立运行 |
| `证明我是一个自律的人` | 预先指定结论，容易诱导模型选择性取证 | `自律习惯的建立与中断：记录计划、执行、失败和恢复` |
| `我是否患有焦虑症` | 日记模型不能进行医学诊断 | `焦虑与不确定感：记录明确担忧、触发事件和应对方式` |
| `别人为什么不喜欢我` | 要求推测他人内心，缺少可审核证据 | `人际疏远与冲突：记录具体互动、自己的感受和后续变化` |
| `我未来会成功吗` | 属于预测，不是历史日记提取 | `长期目标的形成与推进：记录行动、阻碍和阶段性成果` |

## 试跑与全量运行

一个运行会冻结主题、日期范围、598 篇开发基线来源及 Ollama 参数。日期范围只决定其中哪些来源是 eligible。

- 小范围试跑适合验证主题是否过宽、相关性判断是否准确、证据引用是否可靠。
- 小范围运行完成后，不能把同一运行的日期范围扩大，也不能把它的观察复制到另一个全量运行。
- 若需要一个覆盖全部 598 篇冻结来源的统一摘要，必须新建日期覆盖全部来源的运行，并让该运行独立处理 598 篇。
- 可以另建只覆盖剩余日期的运行，从而避免再次调用试跑月份，但它会得到另一个独立摘要，系统当前不会把两次运行自动合并成一个全量摘要。
- 质量加固版每篇 eligible 日记至少调用一次范围分桶，出现 relevant/uncertain 时再调用一次观察合成，因此首次证据处理最多为 `eligible × 2`次。所有观察审核后，有保留观察的首摘要最多再调用一次；全部拒绝时不调用模型。

人物关系图不是当前主题时间线的前置条件。在稳定的人物别名合并、关系类型审核和句子证据边界建立前，自动关系图会把“他/她/老师/同事”错合并为人物事实。本轮先用 `uncertain` 保留边界；后续若实现人物层，应将“人物候选—别名—关系—原文证据”做成独立可审核派生数据，不直接把模型推断写成关系事实。

因此，推荐先用一个代表性月份验证提示词和参数；确认结果质量后，再决定是否值得为该主题执行一次完整的 598 篇运行。不要为了“凑齐主题数量”批量运行价值不明确的主题。
